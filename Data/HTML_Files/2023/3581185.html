Machine learning is applied in a multitude of sectors with very impressive results. This success is due to the availability of an ever-growing amount of data acquired by omnipresent sensor devices and platforms on the internet. But there is a scarcity of labeled data which is required for most ML methods. However, generation of labeled data requires much time and resources. In this paper, we propose a portable, Open Source, simple and responsive manual Tool for 2D multiple object Tracking Annotation ( TmoTA ). Besides responsiveness, our tool design provides several features like view centering and looped playback that speed up the annotation process. We evaluate our proposed tool by comparing TmoTA with the widely used manual labeling tools CVAT , Label Studio, and two semi-automated tools Supervisely and VATIC with respect to object labeling time and accuracy. The evaluation includes a user study and pre-case studies showing that the annotation time per object frame can be reduced by 20% to 40% over the first 20 annotated objects compared to the manual labeling tools.

1 INTRODUCTION

Machine Learning (ML) is currently applied in virtually every sector. ML is being developed over time in a perpetual manner, but for the efficient operation, the quality of data utilized for ML is essential.

The data used as an input for ML can be in many forms including audio, video, and others. In most of the cases, the availability of unlabeled data is significantly higher compared to labeled data. According to Cognilytica [ 5 ], 80 $\%$ of the time of artificial intelligence or machine learning projects are spent on data collection, organization and labeling as a pre-processing part and most of the ML teams cannot afford to spend this huge amount of time. Acquiring labeled data also becomes expensive if the labeling includes domain experts. According to Krenzer et.al [ 12 ] in most cases, domain experts have minimal time resources for data annotation, while on the other hand, data annotation is a highly time-consuming process and reduced annotation time can ease this dilemma.

In this paper we present an easy to use, highly responsive annotation tool that allows purely manual labeling of multiple 2D objects in video data. Automated and semi-automated user support has not been used on purpose on the one hand to avoid domain specification and on the other hand to keep the tool highly responsive. However the techniques used for speeding up manual annotation might be applicable to semi-automatic tools as well. The presented tool is compared to the also purely manual and widely used annotation tool s CVAT [ 17 ] and Label Studio [ 9 ] as well as the semi-automatic tools Supervisely [ 16 ] and VATIC [ 4 , 23 ] in terms of annotation speed, which can be reduced by approx. 20-40% by our tool. Furthermore, we evaluated annotation accuracy and statistical significance. Our contributions are

  • design and implementation of a highly responsive multiple object annotation tool for video data with several new features that include view centering, looped playback, and visibility order navigation, and
  • a user study that validates the significant reduction in labeling time.

The TmoTA tool is Open Source an can be downloaded from https://github.com/sgumhold/TmoTA .

2 RELATED WORK

The idea of collecting large labeled data sets emerged in the early 1990s[ 3 ]. Over time, various methods have been developed to generate labeled data. The methods used are mainly dictated by two characteristics: the type of annotated medium and the type of annotation labels. The annotated medium can be of any type, for example: image, audio, video, sensor data, text data etc. Whereas, the type of annotation labels depends on the medium of the data and can be bounding box annotation, polygon annotation, landmark annotation, linguistic annotation, text classification etc. Depending on the medium, different display and corresponding annotation methods have been proposed. While some tools, like the browser-based annotation tool VGG Image Annotator (VIA) , introduced by Dutta et.al [ 8 ], are designed for multiple data types (images, video and audio). Other tools, such as the image annotation tool LabelImg [ 20 ], are only able to handle one type of data (image).

To ensure the performance of annotation tools, the second important component is the label type. Here, beside others, a classification label, 2D or 3D bounding boxes (with tracking or without), object behaviour, object shape and semantic or instance segmentation can be performed. Also with the label type, there are tools that support multiple types and tools that specialize on a single type. Intel s CVAT [ 17 ] is a prominent example of the tools, that support multiple label types. It is a free and open source annotation tool for videos and images and uses a client-server model. Another example is SALT , introduced by Stumpf et.al [ 19 ]. They presented a semi-automatic labeling tool for labeling RGB-D video sequences. For the labeling process, they generated 3D bounding boxes with 6 degrees of freedom (DoF) poses along with pixel-level instance segmentation masks for both RGB as well as depth. Yuen et.al [ 24 ] present LabelMe , a tool for object segmentation in videos. Besides the object outlines defined by polygons and the object classes, information about the object movement is also labeled. Microsoft's Visual Object Tagging Tool ( VoTT ) [ 15 ], on the other hand, is an open source semi-automated tool that specializes in the creation of 2D bounding rectangles.

Specialization on a media and / or annotation type allows on the one hand to reduce the number of UI elements, which can lead to a simpler operation. On the other hand, interaction processes can be greatly simplified, thus saving user interaction effort.

Labeling tools can furthermore be divided into manual and semi-automatic. With manual tools, the user specifies all annotation data entries on his own. CVAT [ 17 ], Label Studio [ 9 ] and labelImg [ 20 ] are examples for manual tools. In semi-automatic tools, suggestions are calculated and validated and/ or improved by the human, like in Supervisely [ 16 ], TSLAB [ 6 ], SALT [ 19 ] or the video annotation framework proposed by Krenzer et.al [ 12 ]. This aims to reduce the workload for humans and to speed up the annotation process. This speed-up depends on the application domain. Another way to automate annotation is to automatically decide which frames should be annotated. This can be done by simply sampling frames in a fixed rate like in the Video Annotation Tool from Irvine, California by Vondrick et.al [ 23 ], which has problems, when the object movements are very fast and unstable. With visual interpolation and frame selection guiding, Kuznetsova et.al [ 13 ] introduced a more sophisticated approach. Here the visual appearance of an object is tracked and suggestions for which frames should be annotated are calculated. According to Krenzer et.al [ 12 ] the automation can speed up the labeling process by a factor of 20 and according to Stumpf et.al [ 19 ] by a factor of 8.55 up to 33.95 depending on the label type. However, training models need to be domain specific in most of the cases, annotating new domain data is therefore difficult in some circumstances. Further using active learning requires longer computation time compared to manual annotation tools, which can reduce responsiveness.

Von Ahn et.al propose two gamified methods with ESP [ 21 ] and Peekaboom [ 22 ] in order to add entertainment value to the tedious, usually boring annotation work. In the ESP Game, images are shown to multiple players. The players suggest fitting terms separately from each other. The goal is to propose the same term as quickly as possible. Through this game it is possible to add classification labels to pictures. In Peekaboom , again two players play together. One player gets a picture and an associated term. The second player starts with a black picture. Player 1 now uncovers parts of the picture for player 2 until the latter has guessed the term. The goal is to guess the term as quickly as possible. With this system, areas can be annotated that best describe the object. Although these approaches make annotation fun, it increases the time required to annotate an image significantly.

In this paper we show that a highly responsive design of a labeling tool can reduce annotation time significantly. Our techniques can help completely manual tools like ours but also semi-automatic tools that are based on labeling of a subset of the data.

3 METHODOLOGY

As described earlier specialization on label type and media type can simplify the interaction process and the UI. Therefore, we decided to just support 2D tracking boxes on videos. We decided to continue with a manual annotation tool, because on the one hand no complex calculations are necessary, that reduce the responsiveness of the tool. On the other hand, the comparability to available tools can be better guaranteed and the concepts of a manual tool can probably be better transferred to semi or fully automated tools than vice versa.

The following requirements must be met by any multiple object annotation tool:

  • creation and manipulation of objects
  • support for multiple appearances of an object
  • creation and manipulation of bounding boxes
  • deleting objects or appearances
  • adjustable object types
  • import and export of annotation data

Furthermore, we identified the following aspects as key for competing and improving on other annotation tools:

  • fast installation of tool (see section 3.1.1 )
  • fast setup of video labeling session (see section 3.1.1 )
  • highly responsive and intuitive interactions (see sections 3.1.4 , 3.1.5 and 3.1.6 )
  • steep learning curve
  • minimization of necessary user input actions (see sections 3.1.5 and 3.1.6 )
  • efficient per object appearance validation of annotations (see section 3.1.8 )
  • occlusion handling (see section 3.1.9 )
  • redundancy free format (see section 4.2 )

3.1 Interaction Concept

3.1.1 Installation and Start. As efficient handling of video data with random access is quite difficult to achieve in a browser based implementation we chose to develop a portable app implemented in C++ with OpenGL instead. This reduces installation to the download and extraction of a file archive like zip. The archive contains three main files: the executable of ffmpeg, the executable of the actual labeling annotation tool and a configuration file including a manuals.

A video annotation session is setup simply by dragging a video or a folder containing per frame image files onto the executable or running the application with a command line argument for mentioned file or folder. The application runs a ffmpeg command to load the video or image sequence data. The resulting data stream is stored as 3d image in main memory. User interaction is made possible instantly by reading the video data asynchronously in a parallel thread. Annotations are stored in the video folder in a file with name automatically determined from the image directory or the video file. This avoids additional user interaction and allows to automatically load previously annotated objects when continuing a video annotation session. During annotation pressing F2 saves all annotations to the annotation file. The configuration file allows to specify all UI configuration parameters discussed below as well as a file name for a line based definition of predefined object types and colors.

3.1.2 Layout. Figure 1 gives an overview of the TmoTA tool with the video view, the object view and the classical user interface. This subdivision is very intuitive, thus commonly used in most annotation tool designs, and therefore known to users. Video view shows the current frame with annotations. Object view shows a time line with one row per object containing one colored rectangle per appearance. The classic UI has collapsible regions for Video information and IO, for Annotation with support to read object type file or select predefined object type sets "Sepia" (developed for an internal research project) or "MOT20" [ 7 ], for Configuration of visualization and interaction, and for detailed information on Objects with access to all appearances and bounding edge information. All buttons and toggles of the classic UI can be operated with shortcuts that are explained with tool-tips shown when the mouse pointer rests over the button.

3.1.3 View and Time Interaction. The user can pan (right mouse button) and zoom (mouse wheel) the video view. The time navigation works by either left clicking into the timeline, using the arrow keys or setting the frame number in the classical menu. The video can be played using the play button or Space . The playback speed can be set in the classical menu or using the PageUp and PageDown keys.

3.1.4 Object Interaction. TmoTA divides objects into appearances to deal with occlusions and leaving and reappearing objects. The appearances are shown as boxes in the timeline. By clicking on a box in the timeline the appearance and its object is selected. Alternatively one can click on the bounding box in the video view to select an object. To deselect an object the user can click outside the bounding box or press Esc . A new object is created by dragging a bounding box in the video view. If an object had been selected, a new appearance is added to this object instead. After drawing the bounding box on the appearances or objects first frame, a second bounding box for its last frame has to be drawn in a later timestep. Appearances can be extended to the left/right by using the left/right Ctrl Key and clicking in the video view. They can be trimmed using Backspace (from the right hand side) or Del (from the left hand side). Tool-tips close to the mouse pointer are used for user guidance of all interactions that create objects or appearances in order to indicates the result of a potential left click.

3.1.5 Box Interaction. We split each bounding rectangle into its four bounding edges. Each bounding edge can be specified by a single pixel coordinate assuming that the type "left", "right", "bottom", or "top" is known. We support floating point precision for sub-pixel accurate specification of bounding edges. For minimal user interaction, manipulating a bounding box can be done in three ways. The first way is to drag and drop the edge or corner to the new position. The second way is to drag and drop the whole box through dragging from further inside of the box. Since most of the changes of a box are minor changes, we developed a third way by clicking where the nearest edge or corner should be. The corner or edge snaps to this position. This only works within a configurable radius to be able to select different objects with one click. We decided against using anchors to manipulate the bounding box. Because using those, the user needs to perform two precise interactions. One to hit the anchor and one to drag it to the desired position. With our interaction modes, the user has to do just one precise interaction and at most one rough interaction to get into the pick range of the edge or corner. Important for improving the efficiency of user annotation was to highlight the action that a left mouse click will cause. In Figure 1 the mouse pointer is close to the bottom edge of the current object which is highlighted by thickening the opacity ramp along the bounding edge.

3.1.6 Linear Interpolation. To minimize user interactions we exploit interpolation of bounding rectangles. Some of the semi-automatic annotation tools compute or track the annotations following an initial bounding rectangle based on a few assumptions. This takes time and, depending on the data set, the results have to be corrected manually. The waiting time for the results often makes such tools unresponsive and thus reduces the quality of experience. Many movements happen either in uniform or uniformly accelerated motion. Therefore, linear and quadratic interpolation are especially interesting as interpolation methods. However, since e.g. in vehicle data sets the camera is not static, the camera motion has to be combined with the object motion. This makes more complex interpolation methods less appealing. Early user feedback suggested, linear interpolation is preferred over cubic spline interpolation. This might be, because it is more difficult to predict the result of higher order interpolation schemes compared to linear ones and often a similar number of annotations were needed. Therefore for all edges of a video frame where the value is not explicitly defined by the user, the bounding edge is interpolated linearly from the closest frames in forward and backward direction where explicit bounding edge information is available.

3.1.7 Annotation Strategy. The interaction concept for defining object appearances ensures that bounding rectangles in the start and end frame of an appearance are labeled first. The best strategy to proceed with labeling the rest of an appearance turned out to be as follows. The user inspects the automatic interpolation and repeatedly corrects the video frame of maximum mismatch till the bounding rectangle is precise up to a few pixels along the whole appearance.

3.1.8 Object Appearance Validation. To efficient validate the precision of objects annotations we provide ping-pong playback and view-centering.

Ping-pong playback toggles playback direction at beginning and end of the video such that it plays forth and back all the time. Furthermore, ping-pong playback can be restricted to a single appearance of an object, which can be toggled in the UI or with R . Together with playback speed adjustment this allows for detailed inspection of an object appearance through repeated walk through.

View-centering allows to adjust the view center of the Video View to the currently selected object. It can be toggled in the UI or with C . While active, every change to the frame index during playback or through user interaction causes a re-centering attempt, which checks whether currently an object is selected and whether this object is annotated by a rectangle in the current frame. If a current focus rectangle is available, the Video View center is adjusted to the center of the focus rectangle independent of the current zoom level. As a result the current object is always centered during ping-pong playback which is typically restricted to a certain appearance of the current object. This significantly simplifies appearance validation for the user as the object is always centered in the Video View during playback.

3.1.9 Occlusion Handling. Especially, for videos with a large number of pedestrians, bounding rectangles can overlap and occlude each other a lot. This makes selection of the current object difficult. Furthermore, even if the current object is selected correctly occlusion by other objects can hide bounding edges of the current rectangle. To resolve the selection problem we support cycling through the set of all bounding rectangles, the mouse points to with Shift - or Ctrl -Mouse Wheel. Figure 2 shows a case where three rectangles overlap at the mouse pointer location. If the mouse hovers over an overlap of at least two rectangles we blend in a text showing the currently topped rectangle and the number of overlapping rectangles in parenthesis. When an object is selected, we allow to toggle an object focus mode with the Square button in the classical menu or the F key such that all other objects but the current one are hidden.

4 IMPLEMENTATION

The labeling tool we present has been developed using the Open Source cgv framework [ 18 ].

4.1 Rendering

In TmoTA the video frames are stored in main memory and only the current frame is transferred into a 2D texture before each rendering process. The data transfer from CPU to GPU memory does not negatively influence the rendering frame rate. We currently assume that the complete uncompressed video fits into main memory. In a future version this assumption could be dropped by a sliding window strategy that restricts the in memory part of the video to a window around the currently processed video frame. However, most of the videos used for machine learning are short videos with low resolution, since ML models usually have a very high memory demand.

Video view and object view are rendered with OpenGL v3.0. The current object is shown with an inverted rectangle that blends object color over the whole video frame except inside of the bounding rectangle. This has the advantage that perception of the current object is not hindered by color blending which reduces the perceivable brightness contrast with increasing blending opacity. We developed two custom tailored shader programs - one for rendering the current object with a quad that covers the whole video extent. The bounding rectangle of the current object is passed to the shader program by a uniform variable of type vec4 . The boundary of the rectangle is additionally marked by a ramp in the blending opacity. This opacity ramp is increased in width for highlighting of bounding edges. The second shader program is used to render the bounding rectangles of all other objects with the boundary opacity ramp placed to the inside. The result can be seen in figure 1 .

4.2 Data structure

Our data structure stores only the bounding information explicitly defined by user interactions as illustrated in Figure 3b . Bounding information is organized on the top level as an array of objects, where each object stores object type and a comment as well as an array of appearances. Each appearance stores indices of the first and the last video frame as well as four arrays for left, right, bottom, and top bounding edge. Each of these arrays contains pairs of frame index and coordinate only for frames where explicit information has been specified by the user. A pseudo json representation of this data structure can be seen in Figure 3a . To access potentially interpolated per frame bounding rectangles, we first check whether the current frame is contained in one of the object appearances with a linear search as the number of appearances is typically rather small. In a second step we apply for each of the four bounding edges a binary search over the corresponding vectors of frame index-coordinate-pairs returning found coordinates or interpolated values in between. The UI as well as the stored json annotation file reflect exactly this data format. There are several binary and text based json formats to choose from. Furthermore the annotation data can be exported in the MOT Challenge format.

5 EVALUATION

During development we conducted two pre-studies to improve the tool addressing user feedback and test its performance. For these pre-studies, we used CVAT [ 17 ] as comparison. To validate our findings, we also conducted a user study comparing TmoTA against CVAT [ 17 ] and Label Studio [ 9 ] as they are free and open source manual annotation tools capable of object tracking using linear interpolation. We also compared it against the semi-automatic tools Supervisely [ 16 ] and VATIC [ 4 , 23 ] to check if the speeds using tracking features are reachable using linear interpolation. CVAT also allows to use trackers of different kinds. As in a real world scenario participants could decide to use them or not.

5.1 Setup Speed

Installing CVAT and all needed dependencies requires about 30 minutes. Setting up an annotation session takes approximately 2 minutes. The installation of Label Studio requires less then 10 minutes with similar project setup times as CVAT . Supervisely as a cloud-service requires a sign up. An installation is not needed. The time to setup a new project is similar to CVAT and Label Studio . Since TmoTA does not need installation and a session can be started by a single drag & drop interaction, a session can be created within seconds. The java-script version of VATIC [ 4 ] runs a local website in a browser. Here also just the download and extraction time is needed.

5.2 Pre-Study 1

For the first pre-study, we included two non-expert participants using one tool each to annotate 5 objects in a 204 frames long dash-cam video. To perform the labeling precisely using TmoTA , 10.04 minutes were required and 21.35 minutes using CVAT . Figure 4 illustrates the same annotated objects using TmoTA and CVAT .

With switched tools the participants then annotated 584 frames in pedestrian video with static camera. With TmoTA 17.22 minutes and with CVAT 33.41 minutes were required.

User feedback indicated, that it is necessary to have highlighting of the edges, that will be changed by an action, which was missing before. Furthermore the object occlusion handling was introduced after this pre-study, as well as the drag and drop interaction for moving a bounding boxes.

5.3 Pre-Study 2

For the second pre- study, we invited 2 experts in annotation and 6 non expert participants (all having experience with visual computing tools) to label 17 objects from two different videos with 202 and 179 frames using CVAT and TmoTA (in its improved version). Video 1 was acquired with a moving camera and video 2 with a static camera. Both pre-studies were guided and supervised all the time. At the start, each participant was introduced to the tools and the to be labeled objects in the two videos. The instructor was sitting next to the user, watching him/her and answered potential questions. To avoid a bias in the tool order we randomly chose the tool order for each participant. The users had the freedom to choose whether to start with video 1 or video 2.

Annotation time per object for each user was recorded by the instructor using a manual stopwatch. We measured time per object appearance and calculated time per object and total annotation time per video. As the 17 objects appeared in different number of frames, we computed the per frame labeling times and averaged them for each tool over all participants. As our tool was always faster, we can show averaged per frame labeling times as stacked bar chart in Figure 5 on the left and the right shows the percentage that our tool was faster. Considering the overall labeling time TmoTA reduced CVAT labeling time by 38% up to 61%. Averaged over all participants, TmoTA reduced labeling time by 48% basically halving the time. To evaluate the statistical significance of the time measurement results, we first inspected whether our data follows a normal distribution or a student's t-distribution. For this we interpreted each object as an experiment with one sample drawn per participant (separate for each tool). To better analyze the different per object distributions, we computed all averages and standard deviation to re-normalize the samples to a uniform normal distribution with mean zero and standard deviation of one. The transformed samples were unified and their distribution was inspected visually. It was neither close to a normal nor to a student's t-distribution nor to any other distribution we are aware of. But the distributions for the two different tools looked very similar. We therefore performed the non-parametric one-sided Wilcoxon Signed-Rank test with a significance level of α = 0.01 with the hypothesis that per frame annotation time distributions for both tools are the same. The test failed for all objects with a p-value of p = 0.003906 and a quite high standardized effect size of 0.87. We could therefore conclude that for each object our tool was faster with a significance level of 99%.

To evaluate the accuracy, we calculate the Multiple Object Tracking Accuracy ( MOTA ) as proposed in [ 1 ]. The bar chart in figure 6 on the left shows similar accuracy for both tools validating the comparability of the time measurements. The mean MOTA score for CVAT is 70.75 with a standard deviation of 23.05. For TmoTA it is 81.52 with a standard deviation of 7.49.

For the user study, each participants were asked to answer 10 questions from System Usability Scale - (SUS) questionnaire [ 11 ] to determine the usability. To determine the usability, we used (SUS) [ 11 ] combining positive and negative questions together. In such cases, the participants need to think more before answering. From this study, almost all the participants agreed to have a better feeling regarding TmoTA except participant 8. However, for participant 8 both the tools are good as the CVAT SUS score is 75 and TmoTA SUS score is 70 illustrated in figure 6 . For the overall result, CVAT SUS average is 61.56 resulting in a good system and TmoTA SUS average is 82.81 indicating an excellent system.

5.4 User Study

To verify our findings and to include other tools, we conducted another study using the above mentioned tools. Here 17 students (all non experts in annotation) participated. During the study each participant had to label two out of four videos (containing 10 objects each) in two assigned tools. All videos contained driving/pedestrian scenes. All participants had to use TmoTA for a direct comparison. This means that there is considerably more data available in the evaluation for TmoTA than for other tools. The order of the tool as well as the videos were assigned and swapped over different participants, to mitigate advantages due to learning effects. Multiple participants conducted the study at the same time and there was just one instructor. After a short introduction to the task and the steps in the study, the participants had to learn their tools using tutorial videos. A stopwatch tool was provided showing the user the object to annotate and for measuring the annotation times. This tool can be seen in Figure 12a . The instructor answered questions of the participants during the study. The participants measured the object annotation times by themselves. Statistical values for the measures object annotation times can be seen in Table 7a . Since different object have different number of frames they appear in and participants might annotate the same object with different number of frames, the object frame annotation time was calculated (by dividing with the number of frames the participant has annotated). The values for these are listed in Table 7b . In Figure 8 the mean values are plotted next to box plots of the whole data series. As one can see in the per frame data, TmoTA is about 20% to 40% faster than its competitors CVAT and Label Studio that also use linear interpolation. The semi-automated tools Supervisely and VATIC are 20% to 30% faster than TmoTA . Since we only tested one tool at a time against TmoTA , we have four p-value scores to represent the significance of these results. The p-value for the paired, one-sided T-Test of the object frame annotation time between TmoTA and CVAT is 0.0357. For TmoTA and Label Studio it is 0.0042. These indicate significant improvements and validate our previous findings. The p-value between TmoTA and Superviesly is 0.0628 which does not imply a strong significance as well as the p-value between TmoTA and VATIC 0.1785.

In Figure 9 one can see the average time over all users to annotate their first, second etc. object. The figure contains dotted trend lines, representing the learning curves for the tools. One can see, that manual tool have a learning curve, while the semi-automated tools have relatively constant annotation times starting with the first object. Therefore no training is necessary to use the tool effectively. But it also can be seen, that all tools except Label Studio manage to get into a narrow range after about 15 objects. Here it would be useful to have a longer user study analyzing if semi-automated tools can keep the advance over the manual labeling tools for a higher object number.

Within the manual tools, TmoTA has the lowest curve and manages it very fast (after about 6 objects) to close the gap to the semi-automated tools.

The participants of the user study were asked to answer the System Usability Scale - (SUS) questions. The mean SUS scores are depicted in Figure 10 . One can see, that CVAT has the highest score and TmoTA has the second lowest score. We also asked the participants which tool they would prefer. Most of the CVAT users preferred CVAT over TmoTA . All users of Label Studio preferred TmoTA . All other tools had a split in recommendation.

To asses the quality of the annotations, we calculated common HOTA and CLEAR MOT tracking quality metrics against a predefined ground truth annotation, which was not given to the participants [ 2 , 14 ]. In Figure 11 , box plots for these metrics are shown. It can be seen, that VATIC has the worst results in all metrics. This indicates, that this tool might lead the user to be not as precise as for the other tools. Label Studio has a bad HOTA score as well. All other tools lie close together. 6 DISCUSSION AND LIMITATIONS

Our case study shows a significant improvement in object frame annotation time over other manual labeling tools, while being not very significantly slower than semi-automated tools. One way the speed up against Label Studio can be explained is, that in Label Studio the hotkeys for frame navigation contain the left Alt key and the arrow keys, which requires the user to use two hands on the keyboard decreasing overall labeling performance. The improvement over CVAT is probably due to our fast bounding box interaction. Most of the bounding box changes are relatively small. Therefore the one click solution speeds up the correction of the box. Also CVAT uses circles as anchors on edges, which needs more precise interactions than our tool.

Even though we improved the annotation speed over CVAT and Label Studio , our SUS score is very far behind the score of CVAT . This discrepancy between the SUS scores from our pre-study and our user study, might be due to the different instruction types (sitting next to the user and showing vs. video instructions without sound) or due to the experience of the first participant group in visual computing tools. Therefor the intuitiveness of TmoTA for inexperienced users needs to be increased. I.e. by using different hotkeys or choosing more explaining button names in addition to using tool tips. Another idea to increase the SUS score is to introduce a simple mode with reduced functionality (i.e. trimming and extending appearances) which might even improve annotation speed for inexperienced users, by reducing their mental overload. Furthermore, a tutorial mode, including step by step instructions could help. An often criticized point by the participants is that a revert/redo functionality is missing. This functionality might also increase the SUS score significantly because the user does not need to act cautiously for example when deleting objects.

Finally, the current implementation of TmoTA is limited to videos that fit into main memory.

7 CONCLUSION AND FUTURE WORK

In this paper we introduce TmoTA , a highly responsive, easy to use and fast annotation tool using 2D bounding rectangles for multiple object tracking. TmoTA is portable, eliminating the need for a time-consuming installation process where no additional software is needed. Because of this and the simple and fast drag & drop based session launch, startup time for annotating a video is significantly reduced. Through a multitude of features like highlighting, view centering, looped playback, user friendly bounding box interaction, and occlusion handling, it is possible to reduce the average annotation time for an object frame by 20 to 40% compared to the widely used manual annotation tools CVAT and Label Studio for the first 20 annotated objects, maintaining the accuracy compared to other annotation tools. In future work we want to investigate whether the above mentioned techniques can also improve performance of semi and fully automatic tools. Furthermore a longer user study would be useful to validate that after training participants with a high number of objects our tool is still superior to other manual labeling tools and that semi-automated tools are still superior over our tool.
